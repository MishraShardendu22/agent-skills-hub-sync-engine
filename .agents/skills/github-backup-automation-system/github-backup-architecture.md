## 2. Service Responsibilities & Configuration Modules

### Dashboard Application (`src/apps/github-backup-dashboard/`; legacy `frontend/`)
- **Framework**: Next.js 16 App Router with Turbopack, Tailwind CSS, Biome linter, TypeScript.
- **Design system**: `@mishrashardendu22/observatory-tokens` and `@mishrashardendu22/observatory-ui` from [`MishraShardendu22/observatory-ui`](https://github.com/MishraShardendu22/observatory-ui), installed from a GitHub release tarball (`package.json`). Tokens are CSS custom properties (dark first, light by device preference); components ship as TypeScript source that Next.js transpiles (`transpilePackages`). `/` is a public landing page (`src/app/(marketing)/`), the app is under `src/app/(app)/` with the overview at `/dashboard`.
- **Sites**: `src/apps/github-backup-design` (Next.js static export, the design system's website on the same release tarballs) and `src/apps/github-backup-docs` (Docusaurus over `docs/`, CommonMark, autogenerated sidebar). Both use pnpm and deploy to Vercel with their folder as the root directory; CI job `Sites (design & docs)` lints, type-checks and builds them.
- **Responsibilities**: Unified Dashboard, AI Chat Interface, Vector Search Playground, Real-time SSE Log Streaming, Human-in-the-Loop Action Approvals.
- **Config**: `src/apps/github-backup-dashboard/src/config/env.ts` for client-safe constants and `src/config/server-env.ts` (server-only) for `BACKUP_API_URL`, `AGENT_API_URL`, `SERVICE_CREDENTIAL` and the deprecated `INTERNAL_SECRET` (`getServerEnv()`) and the sign-in settings (`getAuthEnv()`), read at request time (Never call `process.env` directly in UI components).
- **Backend access**: Browser code only calls the same-origin proxy (`/api/proxy/backup/*`, `/api/proxy/agent/*`, rules in `src/lib/proxy/`); server components and server actions (`src/lib/server-api.ts`) call the Go API directly with the request's session JWT as `Authorization: Bearer` (without a session, `serverFetch` sends no credentials, like the proxy, and the API decides). The dashboard's own credential (`SERVICE_CREDENTIAL` in `X-Service-Credential`, else the deprecated `INTERNAL_SECRET`; `src/lib/service-auth.ts` is the only place that reads either) is used only server to server: the account lookup at GitHub sign-in, the landing page's owner numbers (`LANDING_PUBLIC_STATS=true`) and the Observatory's password login. The backup proxy forwards only the `GET` calls browser code makes (`BACKUP_PROXY_OPERATIONS` in `src/lib/proxy/core.ts`; `browser-calls.test.ts` fails when the two drift). Calls to the Go API go through clients generated from `contracts/openapi/{identity,runs,insights}.json` (`src/lib/api/generated/`, `pnpm run api:generate`, never edited by hand; `src/lib/api/clients.ts` with openapi-fetch); the pre-commit hook and CI regenerate them and fail on a difference.
- **Auth**: Sign-in routes under `src/app/api/auth/*` (logic in `src/lib/auth/`): GitHub OAuth with PKCE, then the account from the API's `POST /api/internal/accounts/github` (the API's `SIGNUP_MODE` decides who may sign up; the dashboard has no allowlist), or the Observatory password login (account 1). The session JWT (HS256, `JWT_SECRET`, `iss`/`aud` `github-backup`, `account_id` required) lives in the httpOnly `ghb_session` cookie; both proxies and `serverFetch` send it as a Bearer token and never add `INTERNAL_SECRET` to a browser's request. Account pages: `/settings/tokens`, `/settings/agents`, `/link` (server actions in `src/lib/account-actions.ts`). Never store tokens in `localStorage` or forward a browser `Authorization` header; cookie-authenticated writes must pass `isCrossOriginRequest`. Login gate: `src/proxy.ts`, on by default once `GITHUB_OAUTH_CLIENT_ID` or `JWT_SECRET` is set (`DASHBOARD_REQUIRE_LOGIN=false` turns it off). Setup: `docs/AUTH_SETUP.md`.
- **Product analytics** (PostHog Cloud US, `docs/ANALYTICS.md`): off without `NEXT_PUBLIC_POSTHOG_KEY` (build time); posthog-js starts in `src/instrumentation-client.ts` unless analytics is off: on by default, off with Global Privacy Control (`navigator.globalPrivacyControl`, `Sec-GPC`) or after *Turn off analytics* (`ghb_analytics_consent` cookie on the shared parent domain, `effectiveConsent()` in `src/lib/analytics/consent.ts`). Send events only through `track()`/`trackOnce()` (`src/lib/analytics/client.ts`) and `captureServer()` (`server.ts`, inside `after()`), with names and property types from `events.ts`; never personal data (no email, login, repository names, message text; the person is the account id). Keep `privacy.ts`'s rules (masking outside the public pages, nothing from `/api` or `/ingest`, URLs without query strings except `utm_*`). `/ingest` is proxied in `src/proxy.ts` with an allowlist of headers, never cookies. Experiments: a key in `experiments.ts`, `useExperiment()` inside `FlagBootstrapProvider` with `getFlagBootstrap()` on a dynamic page. The docs and design sites have small copies of the consent and init logic (keep all three in step) and send to PostHog directly; their `vercel.json` CSP allows only its two US hosts (`tests/test_site_headers.py`).

### AI Observatory Service (`src/services/github-backup-observatory/`; legacy `agentic-observatory/`)
- **Framework**: FastAPI, LangChain, asyncpg, SQLAlchemy, httpx, Jinja2, uv package manager.
- **Responsibilities**:
  - Multi-turn AI Agent reasoning loop (`invoke_agent`, `stream_agent`).
  - Hybrid Search: PostgreSQL Full-Text Search (`tsvector`) + pgvector cosine similarity + Reciprocal Rank Fusion (RRF).
  - Background embedding generation pipeline (`embedding_generations`, `embedding_jobs`, `embedding_chunks`) over run failures, failed results, fixes and investigations only (ADR 0008), fed by background jobs it claims from `public.platform_jobs` (ADR 0013): `observatory.run_failed` for each failed run, the API backfill of a generation, and the drain that embeds with the server key pool within an hourly cap. `JOB_RUNNER=loop` passes in the process (the pool closes after `DB_POOL_LINGER_SECONDS`); on Vercel a cron calls `GET /internal/jobs/pass` with `CRON_SECRET`.
  - LLM concurrency caps per process (`utils/llm_limits.py`): LLM and embedding slots, turns per account, tools per model message.
  - Human-in-the-loop report generation and SMTP email dispatch (`send_report_email`).
  - JWT Authentication for dashboard chat.
- **Config**: `src/services/github-backup-observatory/config/settings.py`.
- **Service credentials** (ADR 0009): it calls the Go API with its own `SERVICE_CREDENTIAL` (else the deprecated `INTERNAL_SECRET`) and the user's `X-Account-Id` (`data/go_backend.py`), and accepts the dashboard's and the MCP server's credentials against the hashes in `SERVICE_CREDENTIALS` (`utils/service_auth.py`, the Python twin of `src/platform/svcauth`) under its own policy by route (`SERVICE_POLICY` in `utils/auth.py`: dashboard `/auth/login`; mcp `/search`, `/internal/reports/email`). It reads accounts through `identity.accounts_v1` (`data/accounts.py`).

### Backup API Service (`src/backend/github-backup-api/`; legacy `backend/`)
- **Binaries** (ADR 0002, 0010, 0017, 0018): one codebase, six entry points. `cmd/github-backup-identity` (the account, tokens, agents, linking workers, the internal account routes, the waitlist), `cmd/github-backup-runs` (backup requests, research consent (ADR 0012), the export of the backup history, the `/v1` run intake; the reaper, the missed-run check, the owner watch and run retention), `cmd/github-backup-insights` (the history, the dashboard's numbers, the logs and live streams), `cmd/github-backup-notify` (an account's alert channels, rules and deliveries under `/api/alerts`; it sends alerts through `notify/sender`) and `cmd/github-backup-billing` (plans, checkouts, subscriptions, invoices and refunds under `/api/billing` and `/public/billing`, the payment providers' webhooks under `/webhooks`; providers sit behind `billing.Provider`, Razorpay in `billing/razorpay`) register `routes.SetupIdentity`, `SetupRuns`, `SetupInsights`, `SetupNotify` and `SetupBilling` on groups built once per app; `cmd/github-backup-api` is the bundle (`routes.Setup`, all five) and the only binary that migrates. Every route is named after its operationId; `routes/services_test.go` checks the partition. A service checks the schema at startup and refuses arguments. Configuration reads only the settings of the parts a binary runs (`config.Parts`).
- **Database roles**: the services connect as `ghb_identity_svc`, `ghb_runs_svc`, `ghb_insights_svc`, `ghb_notify_svc` and `ghb_billing_svc`, the bundle as `ghb_api` (`roles.sql`). runs, insights, notify and billing check sessions and tokens with `tenancy.Resolver` over identity's views (migration `000020`) and forget revoked credentials from `identity.revocations_v1` (`000025`) within 2 s; identity and the bundle use `tenancy.Store`. Route tests can deploy the five services in process, each on its role (`newEnvAsServices`).
- **Framework**: Go Fiber v2, pgxpool connection pool built by `src/platform/pgpool` (`DB_MAX_CONNS` default 10, `DB_MIN_CONNS` default 0).
- **Responsibilities**:
  - Serving read-only `/api/*` endpoints over the runs, results, logs, fixes and analytics the worker writes (the worker writes to PostgreSQL directly).
  - Streaming new `execution_logs` rows over SSE (`GET /api/logs/stream`, used by the dashboard proxy) and WebSocket (`/ws/live`), both fed by one `livefeed` poller that only runs while someone listens.
  - Failing runs abandoned by a stopped worker from a background job (`jobs`), never from GET handlers.
  - Exposing database metrics and system telemetry.
- **Rules**: every `/api`, `/ws`, `/metrics` and `/v1` request resolves one principal (`middleware.Authenticate`, `src/platform/tenancy`): a dashboard session JWT (`Authorization: Bearer`, `JWT_SECRET`), a personal access token (`ghb_pat_`, scopes `read` or `read write`), an agent token (`ghb_agt_`, the `/v1` run intake only), a platform service's own credential (`ghb_svc_`, `X-Service-Credential`; `src/platform/svcauth`, hashes in `SERVICE_CREDENTIALS`), checked after routing against `routes/service.policy.go`, which gives each calling service only its operations and an account rule for `X-Account-Id` (none, owner only, required; `403 FORBIDDEN`, `403 ACCOUNT_NOT_ALLOWED`, `400 ACCOUNT_REQUIRED`), or the deprecated `INTERNAL_SECRET` (`X-Internal-Secret`) acting for the account in `X-Account-Id` (`400 ACCOUNT_REQUIRED` without it on account routes; counted by `ghb_legacy_internal_requests_total`). `github-backup-api service-credential new <name>` makes a credential. With `API_REQUIRE_AUTH=true` (the default) `/api/*`, `/metrics` and `/ws/live` need one of them; `false` lets requests without credentials read the owner's account (local development only). Health endpoints stay public. Every query filters by the principal's `account_id` (another account's id answers `404`); creating, listing and revoking personal tokens, revoking agents and looking up or approving links need a session; `/metrics` needs `INTERNAL_SECRET`. Rate limits run after authentication, keyed on the account, the agent or the real client IP behind `TRUSTED_PROXIES`. Handlers return errors (never `err.Error()` to clients) and must COALESCE nullable columns instead of skipping rows.
- **Config**: `src/backend/github-backup-api/config/config.go`. Listens on `PORT`, then `SERVER_PORT`, then 8080. With `APP_ENV=production` it refuses to start with neither `SERVICE_CREDENTIALS` nor `INTERNAL_SECRET`, or with an `INTERNAL_SECRET` shorter than 32 characters or a published default.

### Backup Worker Service (`src/services/github-backup-worker/`; legacy `backup-worker/`)
- **Framework**: Go CLI (`src/services/github-backup-worker/cmd/github-backup-worker/main.go`, commands in `internal/app`; `run` is the default, flags `--dry-run`, `--only owner/repo`, `--limit N`, `--force`; `login`, `logout`, `auth`, `github-app`, `version`).
- **Installation**: `make setup` (`scripts/setup.sh`, bash 3.2 portable; `scripts/setup.ps1` for Windows, untested) builds `~/.local/bin/github-backup-worker` and installs per-user schedules (systemd user timers, launchd agents or crontab): weekly `run --scheduled` (Mondays 00:00) and hourly `run --pending-only`. While the legacy `/etc/systemd/system/github-backup.timer` is enabled it installs the new units without enabling them and prints the `sudo` command to disable the old one; it never disables it itself.
- **Logins**: `credentials` (go-keyring keychain, 0600 `credentials.json` fallback and index, keychain calls time out), `githubauth` (device flow, refresh with rotation, `gh auth token` import, `StoredTokens` as the run's `config.TokenProvider`), `githubapp` (manifest flow from `githubapp/manifest.json`, `github-app.json`), `openrouter` (PKCE). Guide: `docs/CLI_AUTH_SETUP.md`.
- **Responsibilities**:
  - Listing the repositories of `ORG_ACCOUNT`, `PROJECT_ACCOUNT` and `GITHUB_TOKEN_PRIVATE`, or with a GitHub App login each app installation's repositories (`GITHUB_DISCOVERY=auto`), through `src/platform/githubapi` (`discovery`); a listing error, and finding no installation, aborts the run before anything changes.
  - Change detection from `pushed_at` and the recorded state (`worker_repo_state`: PostgreSQL with `DATABASE_URL`, otherwise the local SQLite `DB_PATH`), no git call for unchanged repositories.
  - Coordinating machines (`runctl`): the `backup-run` lease in `worker_run_lease`, `--scheduled` (skip within `BACKUP_MIN_INTERVAL` of the last completed run), and the `backup_run_requests` queue (`--pending-only` for frequent timers).
  - Bare clones archived as git bundles (default) or `git archive` tarballs, keys `<owner>__<repo>.<ext>` lowercased (`archive`, `src/platform/gitexec`).
  - Storing archives through a sink (`sink`): `git` (clone of `BACKUP_REPO_PATH` in `_Repos`, batched pushes, 100 MiB limit), `local` or `s3`.
  - Recording telemetry to PostgreSQL (`monitor`).
- **Safety rules** (the worker runs unattended from a timer inside a developer checkout):
  - Always run it from its own directory (`make backup` does `cd src/services/github-backup-worker`); `_Repos/`, `_Work/` and the fallback `./app.db` are relative paths.
  - The worker never runs git in the code repository: `app.db` is untracked and ignored; the shared state is in PostgreSQL. Only one run holds the `backup-run` lease at a time; a run without it exits 0.
  - Private repositories are withheld from the git sink unless the destination repository is confirmed private via the GitHub API; directory and bucket privacy of the local and s3 sinks is the owner's responsibility.
  - Archives of repositories GitHub no longer lists are retained (`missing`). Pruning needs `BACKUP_PRUNE_DELETED=true`, two full runs `BACKUP_PRUNE_AFTER` apart that found the repository missing and a 404 from `GET /repos`; it never deletes more than `BACKUP_MAX_DELETIONS` per run, nor in a run whose listing left out a repository GitHub still has (that run exits 1).
  - State is recorded only after the upload or push containing an archive succeeded; no git command runs through a shell.
  - A stored login that cannot be read (locked keychain, corrupt `credentials.json`) fails the run; it never falls back to the environment tokens, which would list less and mark repositories missing. Tokens travel only as `GIT_CONFIG_*` headers (`gitexec.BasicAuthHeader`), never in argv, URLs or `.git/config`; the destination login is scoped to `BACKUP_REPO_PATH`.
  - Tests never touch the real keychain (`keyring.MockInit` in every `TestMain` that reaches it), the network (httptest fakes, including the GitHub App OAuth flow in `internal/fakegithub`) or real schedulers (`tests/setup_script_test.sh` uses a fake HOME and stand-in `systemctl`, `launchctl` and `crontab`).
- **Config**: `src/services/github-backup-worker/config/data.config.go` (full reference in the worker README).
- **SQLite driver**: pure-Go `modernc.org/sqlite` (driver name `sqlite`), so `CGO_ENABLED=0` builds work; the DSN adds `_pragma=busy_timeout(5000)`. Never reintroduce `mattn/go-sqlite3`.

### Shared Go Packages (`src/platform/`)
- `envfile`: every Go service loads `.env` files relative to the repository root (service-local file first, then `src/backend/.env` or `src/services/.env`); `ENV_FILE` selects one explicit file; the process environment always wins.
- `logging`: slog JSON logger used by the API, the MCP server and the worker (`service` attribute, `LOG_LEVEL`, request IDs in the context).
- `pgpool`: the API and worker connection pools (MinConns 0, 1m idle timeout, 30m lifetime, per-service `application_name`).
- `dbmigrate`: the Go schema migrations and their runner (applied by the API at startup and by `make migrate`, never by a backup run), `Check`, which every Go service uses to refuse a database migrated by a newer release, and `roles.sql`, the service roles' grants, applied after the migrations of every run (`migrate --roles` creates the roles; `testdata/role_grants.golden` is the reviewed list). Since `000019` the tables live in the schemas `identity`, `runs` and `observatory`, with `security_invoker` views under the old names in `public`; tests use `pgtest.RolePrefix`, `pgtest.RolePool` and `pgtest.RoleURL` for roles, with an empty `search_path`. Go code names every table's schema (`runs.backup_runs`, `public.platform_jobs`, `public.schema_migrations`); only the Observatory still uses the views (until B7). `roles.sql` stops a run on a service role it cannot limit (superuser-like attributes or another role's membership, as roles made in Neon's Console have), skips a missing one with a warning and takes back grants made by hand. `000019` locks the tables it moves at once without waiting and fails with nothing changed (55P03) when they stay busy.
- `gitexec`, `githubapi`: git runner and GitHub REST client used by the worker (the MCP bundle tools also run git through `gitexec`).
- `pgtest`: integration-test helpers; tests skip unless `TEST_DATABASE_URL` points at a disposable PostgreSQL.
- `ports`: cache, rate-limit, lock and job-queue interfaces with in-process (`memory`), PostgreSQL (`pgports`, migration `000018`) and Valkey (`valkeyports`) adapters; every adapter passes the `portstest` suites (the Valkey ones need `TEST_VALKEY_URL`). `portset` builds them from `RATELIMIT_BACKEND` and `CACHE_URL`; its `Limit` never fails its caller: a backend error, or over 500 ms, counts the event in process instead. The API's and the MCP server's rate limits all go through it.
- `outbox`, `outbox/relay`, `jobs` (ADR 0005, 0011): a producer writes events into its own schema's outbox in the change's transaction (`outbox.Write`; runs: `runs.outbox`, by `runstore.CompleteRun` and the reaper); the relay, a step of the producer's job runner, enqueues one job per subscriber keyed by the event id and marks them published in one transaction; a `jobs.Runner` runs the handlers of its kinds at least once, when kicked after an in-process commit or every 2 minutes only while the pool is in use (never River: it would keep Neon awake). Handlers must be idempotent and name no repository in their errors; payloads carry ids only. `QUEUE_BACKEND` picks the queue (`memory` only for the bundle). Identity relays `identity.outbox` (`account.deleted`, to `runs.account_deleted`, `insights.account_deleted` and `notify.account_deleted`, which first check the account is gone from `identity.accounts_v1`); notify (ADR 0017) consumes `run.failed`, `run.missed` (runs' missed-run check, a step of its runner) and the billing events as `notify.event`, reads the event's data from `runs.events_v1` and sends deliveries through `notify.deliver` and `notify.digest`, with no store of its own beyond the schema `notify`; a runner with handlers also passes after `JobMaxIdle` (12 h) without traffic, so a deletion completes.
- `rollups`: insights' per-account totals of ended runs (`insights.account_rollups`, `000024`), recomputed by the `insights.rollup` job and on a read that finds the row behind `runs.account_versions` (`000021`, kept by triggers); the dashboard, metrics, repos and the MCP server's summary share its formulas.
- Contracts: one OpenAPI file per API service, `contracts/openapi/identity.json`, `runs.json`, `insights.json` and `notify.json`, sharing `contracts/openapi/common.json` (hand-written; `routes/contract_test.go` checks each service's routes against its file and every answer against the file of the service that serves it), `contracts/openapi/observatory.json` (generated, `make contracts-generate`), `contracts/events/` (event schemas). `make contracts-check` refuses breaking changes unless a commit says `Contract-Break: <why>`; an operation that moves to another service's file is compared at its new home. The worker engine's decision is a contract too: `contracts/engine/plan.v1.schema.json` (ADR 0006) with conformance vectors in `contracts/engine/vectors/hand/` (written by people, never from the engine's output) and `vectors/generated/` (`make vectors`), run by the worker's `TestConformanceVectors`; changing a decision is a vector change, refused by contracts-check without `Contract-Break:`.

### MCP Server (`src/backend/github-backup-mcp/`, serverless entry `api/index.go`)
- Transports: stdio for local IDE agents; stateless Streamable HTTP at `/mcp` (`--transport http`, and in `api/index.go` with `/rpc` as an alias) for network clients and multiple instances; legacy SSE (`/sse`, `/message`) only works on a single instance.
- Every HTTP request except `GET /health` must send `Authorization: Bearer <token>`: a personal access token (`ghb_pat_`, checked by the API through `POST /api/internal/tokens/resolve`, else `GET /api/me`, cached 10 s and dropped when the API refuses it on a forwarded call) runs for its account with its scopes; the deprecated `MCP_AUTH_TOKEN` (optional, at least 32 characters) acts as the owner. Agent tokens and session JWTs get 401, a disabled account 403 (`transport.RequirePrincipal`, `auth/`). The server runs no SQL and has no database URL (`DATABASE_URL` is ignored with a warning): every tool and resource calls the API for the caller's account through `tools/apiclient.go`, one typed method per operationId, which `tools/fakeapi_test.go` checks against the contracts; `trigger_backup_run`, `record_backup_fix` (`POST /api/fixes`, with an optional `idempotency_key`) and `send_backup_report` need `write`; archive tools serve the owner only; stdio runs as the account of `MCP_PERSONAL_TOKEN`, else `MCP_ACCOUNT_ID` (default 1). The SSE server serves the public `GET /health` itself (`internal/app/sse.go`) and binds each session to its account.
- Calls to other services (`auth/service.go`, `tools/apiclient.go`): API calls forward the caller's own personal token; for the owner without one (stdio, `MCP_AUTH_TOKEN`) they send the server's own `SERVICE_CREDENTIAL` with `X-Account-Id: 1`, the only account the API's policy lets it name, and refuse another account before the call. Token checks send the credential alone; the Observatory gets it with the caller's account. Without `SERVICE_CREDENTIAL` it sends the deprecated `INTERNAL_SECRET` as before; never both. A malformed credential stops it at startup (`config.Check`, `svcauth.WellFormed`; the Vercel entry answers `503`).
- Entry point `cmd/github-backup-mcp/main.go`; the SSE port comes from `MCP_PORT` (default 8090), never `PORT`/`SERVER_PORT`, which belong to the API in the shared `src/backend/.env`.
- Every tool result passes through the sanitizer middleware (GitHub tokens of every prefix, database passwords, Bearer and Basic credentials, `password=`/`passwd=`/`secret=` values, configured secrets).
- Archive tools resolve archives by exact name inside `BACKUP_ARCHIVE_PATH` only (`worker_repo_state.archive_key`, `<owner>__<repo>.bundle`, `<owner>__<repo>.tar.gz`, legacy `<repo>.tar.gz`); `.bundle` support needs `git` on the host.
- `trigger_backup_run` queues a `backup_run_requests` row for the worker's next run; tools must report failures as tool errors, never as success.

## 3. Database Schema Specification

All Go migrations reside in `src/platform/dbmigrate/migrations/`, are embedded in the binaries and applied by the backup API at startup and by `github-backup-worker migrate` (`make migrate`), both with `MIGRATE_DATABASE_URL` when it is set (the owner's URL, when `DATABASE_URL` is a service role); a backup run never migrates and stops when the database is behind, and every Go service refuses a database that records a version it does not embed. A run is one transaction holding `pg_advisory_xact_lock(dbmigrate.LockKey)`, so concurrent instances cannot race and a failed run keeps nothing; applied versions are recorded in `schema_migrations`. `000000_observatory_tables` creates the observatory tables exactly as SQLAlchemy does, so a fresh database migrates before the observatory has run. Reserved versions: `000008` worker, `000009` API/MCP, `000010` observatory, `000011` accounts, `000012` pre-order waitlist, `000013` and `000014` database guardrails, `000015` BIGINT log ids and log indexes, `000016` run telemetry and research samples, `000017` the run index account deletion needs, `000018` the platform ports' tables, `000019` a schema per service. Later migrations name the schema of every table, in `information_schema` checks too (`table_schema = 'runs'`; `TestCatalogChecksNameTheirSchema`), and recreate a table's view when its columns change. The API prunes old rows hourly (`db.ApplyRetention`: logs 30 days, runs 30 days free or one year paid, never the owner's account).

1. `backup_runs`: Stores each backup batch (ID, status, total repos, duration, timestamps); its error lives in `backup_run_errors` since `000005`.
2. `backup_results`: Per-repository outcome (status, sizes, commit_hash); its error lives in `backup_result_errors` since `000005`. `000009` indexes it for the newest result per repository and the largest archive.
3. `execution_logs`: Structured step-by-step logs, indexed on `run_id` and `created_at` (full-text search runs over `embedding_chunks.content_tsv`, which has the GIN index).
4. `analytics_snapshots`: Aggregated metrics and commit snapshots over time (1-to-1 unique with backup_runs).
5. `backup_fixes` & `backup_run_fixes`: Historical failure resolutions and commit tags.
6. `ai_chat_sessions` & `ai_session_metadata`: Normalized conversation sessions and key-value metadata.
7. `ai_chat_messages` & `ai_tool_calls`: Chat history and granular tool execution telemetry.
8. `investigations`: Saved agent investigation traces, tool calls, and results.
9. `embedding_generations`, `embedding_jobs`, `embedding_chunks`: Vector index and chunk storage with pgvector and deterministic blue-green lifecycle management.
10. `worker_repo_state`, `worker_run_lease`, `backup_run_requests` (migration `000008`): backup worker state, the cross-machine run lease and queued backup requests (other services insert `pending` rows; `target_repo` NULL means every repository).
11. `waitlist_signups` (migration `000012`): the landing page's pre-order waitlist (email, source, date; one row per address, no account), written by the public `POST /public/waitlist`.

| `ci.yml` | push (all branches), fork PRs into `main` | Path-filtered Go / Python / frontend / Docker smoke / scripts jobs plus the aggregate `CI Status` check; one concurrency group per commit on `main`, so no `main` run is cancelled |
| `security-audit.yml` | PRs, push to `main`, weekly, manual | govulncheck, gitleaks (`.gitleaks.toml`), Trivy, pip-audit, pnpm audit, actionlint, zizmor; results in logs and job summaries (private repo on a free plan: no code scanning) |
| `publish-images.yml` | successful CI push run on `main` whose Docker smoke test ran (not `app.db`- or docs-only), `v*` tags on `main` with passing CI, manual (commit must have passing CI) | Images with SBOM and provenance (`linux/amd64` and `linux/arm64`, ADR 0019; an image whose source is not on the commit is skipped with a notice) to GHCR and, with `DOCKERHUB_USERNAME`/`DOCKERHUB_TOKEN`, Docker Hub. `latest` only when no file in the CI `docker` path filter changed on `main` after the commit (its `IMAGE_PATHS` must match that filter). Deploys nothing |
| `release.yml` | `v*` tags | Gate (tag on `main`, `go test -race ./...`), then GoReleaser (`.goreleaser.yaml`): worker and MCP binaries for linux/darwin/windows x amd64/arm64, checksums, notes from `CHANGELOG.md` |
| `pr-review.yml` | non-draft same-repository PRs (opened, synchronize, ready, reopened); `@claude` comments, review comments and reviews by the owner | `claude-code-action`: a read-only review (inline comments, one summary rewritten on each push), and on request an answer or a fix committed to the PR's branch, which reruns CI and the review. Skips with a notice without `CLAUDE_CODE_OAUTH_TOKEN`/`ANTHROPIC_API_KEY`; needs the Claude GitHub App |
| `sync-skills-upstream.yml` | push to `main` touching `.agents/skills/**` | Pushes skills to the hub with `SKILLS_SYNC_TOKEN`; skips when the secret is absent |

- **Runners**: every job has `runs-on: [self-hosted, linux, workstation]`, the owner's four workstation runners (the label is declared in `.github/actionlint.yaml`); give a new job exactly this. Nothing runs on runners GitHub hosts or on another CI provider, and there is no fallback. The runners share one x86_64 machine, its home and Docker daemon: caches stay on its disk (`setup-go` with `cache: false`, `setup-node` without `cache`), per-job directories go under `runner.temp` (pnpm's `dest`, `DOCKER_CONFIG`), the smoke jobs queue in one `concurrency` group, and QEMU emulates arm64 for the publish job. Details: `docs/architecture/current/06-operations.md#ci-runners`.
- **Images**: `ghcr.io/mishrashardendu22/github-backup-{identity,runs,insights,billing,notify}` (one service each, `src/backend/github-backup-api/Dockerfile.service`), `github-backup-{api,worker,mcp,observatory,dashboard}` (the `api` image carries the bundle and the five service binaries; Compose picks one with `entrypoint`) and `github-backup-db-backup` (`deploy/shared/db-backup` with `PG_MAJOR=16`), tagged `sha-<short>`, `latest` (main, never moved back to an older image), `<version>` and `<major>.<minor>`. Go Dockerfiles cross-compile from `$BUILDPLATFORM` and pin `golang:<go.mod toolchain>-alpine3.24` / `alpine:3.24`; keep the `toolchain` line in `go.mod` and the golang tags in sync.
- **Deployments**: Render builds the API's bundle from `render.yaml` (`autoDeploy`); Vercel deploys the dashboard and Observatory from Git. The OCI VM deployments, their workflows and their runner installer were removed on 2026-11-05 (ADR 0007, 0014, 0015 withdrawn). `deploy/shared` holds what the stacks share: Caddy's API routes (`caddy/api-routes.caddy`, routing the API host by whole path segments and serving the same routes on an internal listener `http://caddy:8080` for the dashboard, the MCP server and the Observatory), Prometheus, Grafana and the collector, the dump image (`db-backup`) and `production.env.example`; `deploy/shared/check.sh` validates them. `TestRouteTable` keeps `deploy/shared/testdata/api-routes.txt` in step with the route sets and `deploy/selfhost/check-ingress.sh` sends every route through `Caddyfile.domain`. Self-hosting (`deploy/selfhost`, ADR 0019) runs every service and PostgreSQL 16 with Docker Compose on one Linux machine behind Caddy, in `domain`, `lan` or `tunnel` mode (`compose.<mode>.yaml`, `caddy/Caddyfile.<mode>`, the shared `deploy/shared/caddy/api-routes.caddy`); `install.sh` generates `/etc/ghb/selfhost.env` (every secret, the three service credentials and their hashes), and `ghb` deploys (a dump, `migrate --roles`, start and wait; after a failed start the previous release only when no migration ran, else `ghb rollback --restore` restores the dump), dumps nightly and restores. A setting a service gains goes into `deploy/selfhost/compose.yaml` and `deploy/shared/production.env.example`; `deploy/shared/check.sh`, `deploy/selfhost/check.sh` and `tests/deploy_selfhost_test.sh` run in the deploy-config job.
- **Secrets**: `fnox.toml` (`docs/SECRETS.md`, ADR 0016) holds every setting: profile `dev` (public values; `make dev` runs under `fnox -P dev exec`, `make env` writes `.env`; `DATABASE_URL` is `env = "exec"` so compose keeps its own) and profile `prod` (exactly the keys of `deploy/shared/production.env.example`, checked by `tests/test_fnox_config.py`; secrets age-encrypted with `fnox -P prod set`, owner-supplied ones `if_missing = "error"`). `make secrets` edits it, `make secrets-check` lists what is missing; the pre-commit hook refuses non-ciphertext values, `production.env` and `fnox.local.toml`.
- **Compose**: `docker-compose.yml` reads the root `.env` (`make env`, or `cp .env.example .env` without fnox); `INTERNAL_SECRET` and `JWT_SECRET` are required (`${VAR:?}`); `SERVICE_CREDENTIALS` and each caller's `DASHBOARD_`/`MCP_`/`OBSERVATORY_SERVICE_CREDENTIAL` are optional (empty, the callers send `INTERNAL_SECRET`), as is `MCP_AUTH_TOKEN`. It runs a one-shot migrate (the bundle), the five API services and a Caddy gateway on `:8080` with the shared routes; the other services call the gateway. On a fresh database the migrate job runs first: its migrations (`src/platform/dbmigrate`, from `000000_observatory_tables`) create every table, the Observatory's included, and the Observatory runs no DDL.
- **Smoke test**: `make smoke` / `scripts/smoke-test-stack.sh` starts postgres, the migrate job, the five API services, the gateway, Observatory, dashboard and MCP as an isolated compose project with generated secrets and probes every `/health` (dashboard `GET /`) and a 401 from each API service through the gateway, plus the worker's SQLite startup. CI runs it with `SMOKE_SKIP_BUILD=1` after building the images.
- **Load tests**: `make load-test` / `scripts/load-test.sh` runs `tests/load` (`ghb-load`, Go, no external tool) against a running stack, or starts the smoke stack with its HTTP ports published on loopback (`LOAD_STACK=compose`): health ceilings, insights reads with the owner's session, N linked workers over `/v1`, the per-address limit, SSE streams, the Observatory's public routes, the MCP server. Profiles smoke, baseline (thresholds) and stress; results under `tests/load/results/` (git-ignored), baselines recorded in `docs/LOAD_TESTING.md`. `make estimate` (`scripts/estimate-backup-time.py`) is the worker's run-time model (`docs/CAPACITY_MODEL.md`). Not part of CI.
- **Env examples**: `.env.example` (compose), `src/backend/.env.example` (API + MCP), `src/services/.env.example` (worker + Observatory), `src/apps/github-backup-dashboard/.env.example`.
- **Hooks**: `.githooks/pre-commit` runs fast checks only; `.githooks/pre-push` re-checks the pushed commits and runs the Go, Next.js and Docker builds (`make pre-push`).
